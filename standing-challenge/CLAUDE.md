# Stå på! — Project State

## What it is
A cozy internal site for The Brave's 17 employees to compete on standing-desk time. Pick 30/60/90 min, a timer runs, everyone sees a live pixel-art office (who stands at a raised desk, who dozes at a lowered one), plus today/this-week leaderboards. **Visual delight is the #1 success criterion** — colleagues should think «herregud så gøy og koselig!».

- Design spec: `../docs/superpowers/specs/2026-09-11-sta-pa-design.md`
- Approved room mockup (sprite origin): `../docs/superpowers/specs/mockups/2026-09-11-pikselkontoret.html`
- Brainstorm mockups + figure-builder prototypes (v1–v4): `../.superpowers/brainstorm/` (gitignored, local only)
- Git root is the parent folder; this Next app lives in `standing-challenge/`.

## Room features
- **Heiarop:** tap a colleague → menu with today's total and emojis (standing: 👏🔥💪☕, sitting: ⬆️ «reis deg!», 👀, ☕). `sendCheer` stores it in `cheers` (sender = logged-in user; no self-cheers; 30 s cooldown per sender→receiver). Snapshots carry cheers from the last 8 s (`CHEER_SHOW_MS`, longer than a poll); the room floats the emoji over the receiver's head and the receiver gets a toast. Everything is derived from `now` — no effects/state for animations. Preview with `/dev/room?cheer=1`.
- **Kontorplanten:** a potted plant on a wall shelf (back-left corner on desktop, between the windows on phones) grows through 6 stages with the whole office's standing this week toward `WEEKLY_GOAL_HOURS` (30), blooming at the goal; resets Monday with the week totals. Sign «12/30 t»; tap for the full label.
- **Veggskjermer:** anyone with `employees.remote_from` set (Shobhit in Bergen) gets no desk — they hang on the wall as a pixel TV, rain falling behind them, with a LIVE dot and the place name. Their menu and floating cheers open *downward*: the room clips anything that leaves it, so upward reads as sliding under the header.
- **Fakta-plakaten:** a corkboard with «Visste du?» above it. Tap for a panel with today's fact, its source in small print and «Neste fakta» to page through. The list is `lib/fun-facts.ts` — house rule: every fact traces to a study, a systematic review or a health authority, and `source` names it; where the evidence is weak the fact says so. Up to 280 characters each. `factOfTheDay(osloDayStart(now))` gives the whole office the same fact until midnight. The panel is open/closed from `OfficeRoom` (`factOpen`), not by the poster itself: opening a colleague's heiarop menu puts the board away, so the two never fight over the same patch of wall.
- **Stå til …:** a fifth pill opens `StandUntilDialog` (the `backdrop`/`dialog` pattern from «Står du fortsatt?») with an `<input type="time">` prefilled to `nextHalfHour()`. `minutesUntil()` turns the clock time into minutes **on the client, off the colleague's own clock**, so no time zone ever crosses the wire — the server only ever receives a number of minutes. A time that has passed, or one more than `MAX_ROUND_MINUTES` (4 t) ahead, is refused in the dialog with a hint rather than being clamped. «Én runde til» afterwards offers the same arbitrary length again, by design.
- **Arbeidsklokke:** the wall clock is an `<a>` to Andreas' pomodoro timer (`components/office/WallClock.tsx`), opening in its own tab so a running round is never navigated away from, with «Arbeidsklokke» above the dial and the tooltip on hover. It shares its `top` with `.poster` on purpose, so the two labels sit on one line and the dial lines up with the corkboard; it is centred as a flex column because the label is wider than the dial — and it inherits the phone rule that hides the clock, so the link is desktop-only by design.
- **Kontorhunden:** one dog walks the floor per day, picked by `dogOfTheDay(osloDayStart(now))` — the same day-index trick as `factOfTheDay`, doubled modulo and all, so the whole office sees the same dog until midnight. The list is `lib/dogs.ts`: name, owner and the pixel rects together, so **adding a dog is one entry and nothing else** (the room sizes the box inline from `w`/`h`, which is why a dachshund and a terrier can share one component). Tapping shows the dog's name and pauses the walk with `animation-play-state`, because a dog crossing the room is no fun to chase with a finger. The name is a proper noun, so it goes straight from the data to the label with no i18n key; `owner` is kept as a record of whose dog it is but is never shown. Shipped: Antonio Conte (Anja's), Ginko (Joar's, a dachshund) and Toni (Anders', a lagotto). Toni carries his own outline colour rather than the scene's `OUTLINE` — see the sprite rules for why.
- **Ekte vær:** `lib/yr.ts` fetches MET's locationforecast for `OFFICE_LOCATION` (Aker Tech House, Fornebu) through Next's data cache (`revalidate` 15 min), so MET sees one request per 15 min however many tabs poll; it rides along on every `loadOfficeSnapshot` as `snapshot.weather`, and is `undefined` (= clear sky) if MET is down or slow (3 s timeout). The symbol code for the current hour becomes a `Weather` (`weatherFromSymbol`): cloud, fog or anything falling greys the sky and hides the sun/moon (`weatherSky`); rain, sleet and snow fall as 1px particles in both windows (`precipitation`, a fixed pseudo-random sequence so polling never reshuffles them), stepping whole pixels via CSS `steps()`; thunder flashes. Particles are drawn over the hand-drawn view and under the frame, which is redrawn last to hide the ends of the fall. `prefers-reduced-motion` freezes the rain and drops the lightning. Preview any MET code with `/dev/room?weather=heavyrainandthunder`. The wall screen's Bergen rain is still the static drawing.
- **Admin «sett ned»:** an admin tapping a colleague who is standing gets a two-step button that ends the round. `planAdminStop` is built on `planStop`, so they keep exactly what «Jeg satte meg» would have given them, and the row records `end_reason = 'admin'`. Hidden for non-admins, for people already sitting, and for the admin themselves (who has their own Stop button).
- `scripts/` — `import-employees`, `seed-dev`, `make-icon`.

## Rules & conventions
- UI copy in Norwegian bokmål. Pixel art only for figures/scene — text and buttons use Bricolage Grotesque (headings) + DM Sans (UI), never pixel fonts. The user reacts strongly to visuals: show rendered screenshots/mockups for visual changes.
- All day/week math in Europe/Oslo (`lib/time.ts`); never use the server's local time.
- Rounds are 15/30/60/90 min; 5 min grace for «Står du fortsatt?» (30 s and minutes-as-seconds with `DEV_FAST_TIME=1`, dev only). Expired rounds are closed lazily on read — no cron.
- Two round-length rules, deliberately separate. `ROUND_OPTIONS` (`lib/sessions.ts`) is the list of **pills** — the `RoundMinutes` type and `MyStatus` derive from it, and `isRoundMinutes` now guards only that list. What the **server** accepts is the wider `isValidRoundMinutes`: any whole number of minutes from 1 up to `MAX_ROUND_MINUTES` (240), because «stå til …» produces arbitrary lengths. Adding a pill still means changing three things by hand: the `m === 60` special case in `MyStatus.tsx` (the yellow «go» pill *and* the `status.stand60` label, so a different recommended length means editing two lines); the `isRoundMinutes` test; and the width of the pill row, since each length costs ~75px and the phone budget is ~332px. The DB does not constrain any of it (`round_minutes` is a plain `integer`), so new lengths need no migration and old rows keep their value.
- No `proxy.ts`/middleware: auth is checked in pages (redirect), route handlers (401) and inside each Server Action. The dev Credentials login exists only when `NODE_ENV=development`.
- Keep testable logic in `lib/` with a `*.test.ts` next to it.
- Wall props (windows, clock, noticeboard, wall screens) hang off the wall gradient's own 20% band, not a pixel offset from the ceiling — the room grows downward as rows are added, and a fixed `top` leaves them stranded up there. Two CSS traps in `OfficeRoom.module.css`: a rule added at the end of the file beats the phone overrides in the earlier `@media` block (same specificity, last one wins), so late additions need their own media block at the end; and anything with a `z-index` is a stacking context, so a menu inside it cannot rise above the desk rows (max 20) on its own.
- Wall props are *sized* in px but *placed* in `%`, so they grow into each other as the room narrows: 240px windows at `left: 10%` reached right past the poster at `30%` on anything under ~1200px — which is every iPad. The windows now shrink with the room (`min(240px, 23%)` plus `aspect-ratio: 64 / 36` instead of a second fixed number), the poster sits at `36%` and the clock is centred, which keeps every gap open from the 700px phone breakpoint up to 1920px. Check a new wall prop by sweeping widths, not by eyeballing one — setting `main.style.width` on `/dev/room` walks many widths in a single pass, and stays faithful above the 700px breakpoint because everything on the wall is a `%` of the room element rather than of the viewport.
- Room stacking lives in `ROOM_LAYERS` / `rowZIndex` (`lib/room-layout.ts`), not in scattered magic numbers. A desk row is a single stacking context, so a menu can never leave it — lifting the menu clear of the noticeboard lifts the whole row of name bubbles with it, straight through the open fact panel. That is why only one pop-up is open at a time (see Room features) rather than the row simply being raised.
- A `transform` on an animated container mirrors **everything inside it, text included**. The dog's `walk` animation used to carry `scaleX(-1)` to turn him around, which was invisible while the element held only a drawing — then the name bubble moved in and rendered backwards on the return leg. The turn now lives in its own `face` animation on the `svg`, with the same keyframes, so the container only moves. Pausing still works from one rule, because `animation-play-state` applies to every animation on an element.
- Language (bokmål by default, English when the browser is English or the header toggle says so): the server always renders Norwegian and the client swaps after mount via `components/useLang.ts` (localStorage + `useSyncExternalStore`, exactly like `useSoundSetting`) rather than a cookie, because that keeps the pages cookie-free and cacheable and makes a hydration mismatch impossible by construction — the dictionaries are `locales/{nb,en}.json` behind the pure `t()` in `lib/i18n.ts`, which server actions also use via a `lang` argument passed from the client.

## Figures / sprites
- Figure model: `hairStyle` short|buzz|long|bun|curly, `hair`/`skin`/`shirt` from the palettes in `lib/figure.ts`, `eyewear` none|glasses|sunglasses, `beard` none|stubble|full, `mustache` boolean, `deskItem` mug|plant.
- Sprites are `<rect>`s on a 40×48 grid (figure + desk). In `lib/sprite.ts`, `head(p, f, x, y, …)` draws relative to the face's top-left `x, y` — standing `(7, 11)`, sitting `(7, 17)` — so anything drawn relative to `x, y` works in both poses. Painter helpers: `r(x, y, w, h, fill)` plain rect, `o(…)` rect with a 1px `#120d22` outline, `dots(…)`. Colour helpers: `shade`, `lighten`, `blend`.
- Head avatars use `HEAD_BOX` (18:21) — keep SVG width/height at that ratio or pixels outside the box leak in.
- Adding a coded figure option = type + palette/validation in `lib/figure.ts`, drawing in `lib/sprite.ts`, a chip in `components/admin/FigureBuilder.tsx`, and tests.
- **Drawing at scene scale — learned the hard way on the dogs (three redraws each).** Sprites render at 3×, so a dog is 51–78px on screen. At that size *interior detail does not exist*: the silhouette and one flat colour carry the whole read. Two-tone speckling meant as fur reads as a piebald pattern; a 1px "step" meant as a snout reads as nothing. Spend the pixels on the outline shape, not on texture. A cramped head is the usual culprit when an animal "looks weird" — budget the width first (ear 2, skull 3, snout 2, nose 1 was what finally worked), and widen the box rather than shaving the face. Judge every sprite **at actual size in the room**, not only blown up: the zoomed view flatters detail that vanishes at 3×.
- **A dark sprite needs its own outline colour.** `OUTLINE` (`#120d22`) is near-black, so on a pale figure it reads as a crisp edge but on a dark one it merges with the fill into what looks like a drop shadow. Toni's coat is `#44424e` with his own `#2a2833` line. Equally, a dark pupil disappears into a dark head — his eye is cream.
- **Scene art is plain PNGs, no script.** `sprites/scene/*.png` are imported statically in `components/office/scene-art.ts` (Next reads the size and hashes the name) and shown as-is with `image-rendering: pixelated` — the conversion pipeline below exists only for things that must follow the figure's pose. Window views (`WINDOW_VIEWS`, `left` + optional `right`) are 60×32 transparent layers drawn into `PixelWindow` between the city and the mullion (`WINDOW_GLASS`, `WINDOW_MULLION` in `lib/sky.ts`), dimmed by `sky.outside` so daytime art dusks with the sky; `WALL_TILES`/`FLOOR_TILES` repeat a tile over the room/floor at 3× via `tileStyle` (replacing the CSS colours entirely; `.tiled` drops the plank seams); props use `components/office/SceneSprite` at `SCENE_SCALE` (3), and a strip of side-by-side frames animates with CSS `steps()`. `forMonth` (`lib/scene.ts`) picks the drawing for the Oslo month; `/dev/room?month=10` previews. Lists are first-match, so a one-off month goes above an `ALL_YEAR` entry. Templates `vindu-mal.png`, `vegg-flis-mal.png`, `gulv-flis-mal.png` and `gulv-mal.png` (a scale reference, not a canvas) are written by `npm run sprites`.
- **Hand-drawn art (the user draws these himself):** PNGs in `sprites/hode/` (26×22, head art → `figure.headwear`) and `sprites/pult/` (18×12, desk items → extra `figure.deskItem` values). `npm run sprites` (`scripts/build-sprites.ts`) converts them to rects in `lib/sprite-art.generated.ts` (never edit by hand), and rewrites the drawing templates + palettes (`sta-pa.gpl`/`.hex`) in `sprites/mal/`. The file name becomes the id/label (`rosa lue.png` → «Rosa lue»). Head canvas top-left = face top-left + (−6, −8) (`HEAD_CANVAS`); desk canvas = (20, deskTop − 12) (`DESK_CANVAS`); anchors in `FACE`/`DESK_TOP`. Pixels identical to the template are dropped when a drawing was made on top of it. Pure helpers + tests in `lib/sprite-art.ts`. User-facing guide: `sprites/README.md`. `headwear` is optional in `Figure` so rows saved before it existed stay valid. Examples shipped: `caps` and `katt`.
